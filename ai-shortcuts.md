<div class="content-section">
  <h2>A floating AI assistant that never steals your focus</h2>
  <p>The desktop Arc menu is built as a <strong>non-activating panel</strong>, and that one design decision changes how the whole thing feels. When you press ⌃ Space, the panel fades in over your current window — but your app keeps its focus and your text cursor stays exactly where it was. macOS doesn't flip you to another Space. Your half-typed email doesn't lose its blinking caret. If you change your mind, Esc dismisses the panel and there's no residue on screen, as if nothing happened.</p>
  <p>This isn't a cosmetic detail. It's what makes <strong>AI Writer</strong> possible: Arc reads the text field you're typing in, generates a rewrite or a reply, and writes the result back <em>into that same field</em>. That only works if the field is still focused while Arc works — which is why the panel never activates itself.</p>
  <p>The rest of the interaction is keyboard-first, deliberately. The search field is focused the moment the menu opens, with the first action already selected. Type to filter, press ↑ / ↓ to move, Return to run, Esc to bail out. You never have to touch the mouse if you don't want to.</p>
  <p>Arc also behaves like a system utility rather than an app you have to babysit. Close the main window and Arc keeps running in the background — a menu-bar item on macOS, a tray icon on Windows — with the hotkey alive from any app. While an action runs, a small click-through overlay shows its name; you can keep working underneath it.</p>
  <p>And the summon key itself is yours to change. If ⌃ Space already belongs to Spotlight or your input method, open Settings → Activation, press Record, and pick a different combination. Arc detects conflicts with its own actions and names the one that owns the key, so you never end up with two actions fighting over the same shortcut.</p>
</div>

<div class="content-section">
  <h2>Keyboard-first, from summon to result</h2>
  <p>Three small touches make the menu fast in practice, not just in theory:</p>
  <p><strong>Search filters by name <em>and</em> description.</strong> Typing "summarize" finds AI Summary even though that word only appears in its subtitle. Custom actions filter in the same pass, so with twenty actions of your own, three letters is usually faster than scrolling.</p>
  <p><strong>The search box doubles as a prompt box.</strong> Type a question no action matches — "what are the risks listed here?" — and the menu shows a single hint: <em>Press Return to ask this as a question</em>. Press Return and Arc reads the current screen, attaches it as context, and opens a chat with your question already asked. The answer streams in, and follow-ups stay in context. It's the fastest "ask about this screen" box you'll ever use, and you never had to create an action first.</p>
  <p><strong>Every action can skip the menu entirely.</strong> Each row in the Arc menu carries a keyboard icon. Click it, press the combination you want — ⌥ S, say — and from then on that key runs the action headlessly: no menu, no panel, just the result. Arc suspends its other shortcuts while the recorder listens, so the capture is clean, and it rejects a combination that's already bound, telling you which action owns it.</p>
  <p>On Android, the same philosophy shows up as the floating sidebar: swipe, tap the action, done. The platform differs; the "one invocation, one action" idea doesn't.</p>

<div class="content-section">
  <h2>Custom AI actions: write the prompt once</h2>
  <p>Arc Actions are your own AI shortcuts. Name one, write a prompt, pick an icon, save — and it appears in the Arc menu immediately, ready to run against whatever is on screen. Unlimited actions, and building one takes under a minute. The form has five fields: <strong>Name</strong>, <strong>Prompt</strong>, an icon picker with dozens of options shared across Android, macOS, and Windows, two checkboxes (<em>Capture a screenshot region</em> and <em>Enable web search</em>), and an optional per-action keyboard shortcut.</p>

  <h3>The {screen_text} placeholder</h3>
  <p>When you write a prompt, you control exactly where the screen content lands using <code>{screen_text}</code>:</p>

<pre><code>You are a senior editor. Rewrite the following in plain English, max 120 words:

{screen_text}

Then list any claims that need a citation.</code></pre>

  <p>At run time, Arc substitutes the text it read from the screen at that exact spot. If you omit the placeholder entirely, the screen content is still sent — it's simply appended as context instead of spliced into the middle. Under the hood the placeholder is stripped before the request leaves your device, so an action behaves identically either way. The result: full control over prompt structure if you want it, zero ceremony if you don't.</p>

  <h3>Screenshot-backed and web-search-backed actions</h3>
  <p>Some prompts need eyes, not just text — "what does this chart show?", "read the label on this package", "critique this layout". Tick <strong>Capture a screenshot region</strong> and each run of the action starts with a region selector: drag a rectangle around the relevant part and the cropped image travels with the prompt. The very first screenshot triggers an explicit consent dialog, and if you decline it, text-only actions keep working. <strong>Enable web search</strong> is the other option — it augments the prompt with live results, which is how "fact-check this claim" and "is this pricing still accurate?" work.</p>

  <h3>Bind it, order it, iterate on it</h3>
  <p>Your most-used action doesn't need the menu at all: bind it to a global shortcut and it becomes a single-keystroke command from any app. Everything stays editable — rename it, tweak the prompt as you learn what works, change the icon, disable it without deleting. Changes apply on the next run.</p>
</div>
